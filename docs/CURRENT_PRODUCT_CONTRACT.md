# 当前产品契约

本文只定义用户可见的产品行为与不可破坏的约束。代码地图说明实现位置；具体参数以运行配置为准。代码和本文不一致时，先判断是实现回归还是文档过期，不得仅为迁就现状而改变已确认的产品要求。

## 核心对象

- **任务 Task**：用户工作的主入口，保存目标、材料关联、当前阶段和报告入口。
- **执行轮次 TaskRun**：同一任务的一次执行，轮次身份与 revision 确定后不变；状态和进度会随运行更新。
- **报告 Report**：任务当前可编辑的正文。
- **报告版本 ReportVersion**：不可变历史快照，可用于浏览、前后版本比较和恢复。
- **材料对比**：独立的只读任务，引用某报告及基线版本，不直接修改基线报告。

## 工作模式

| 模式 | 行为 |
|---|---|
| 首次生成 | 解析并理解材料，规划证据问题，提取事实，形成分析和最终结构，组织成文并进入审核 |
| 文档解析 | 解析和理解材料，提供结构化摘要；不要求生成报告 |
| 增量更新 | 在原任务上创建新执行轮次；比较新增材料与活动基线，更新事实/分析并改写受影响内容 |
| 新增材料对比 | 独立分析新增材料相对选定报告版本的新增、补强、更新、冲突、削弱和无关信息；保持基线不变 |
| 交互修改 | 助手解释当前任务产物或形成提案；用户接受后，按操作范围应用或重新执行相关阶段 |

材料对比与增量更新是不同任务：对比结果可作为增量更新的输入，但不会自动替用户改写基线报告。

## 主流程与用户检查点

正常报告流程由材料解析、材料理解、需求讨论（可选）、分析规划、证据提取、冲突核验、综合分析、最终目录、成文组织、写作、质量检查和审核组成。权威阶段顺序与状态值见 [app/workflow/stages.py](../app/workflow/stages.py)；阶段执行见 [app/workflow/controller.py](../app/workflow/controller.py)。

- 协作规划可在材料理解后暂停，让用户补充或修改主题与要求；确认后从分析规划继续。
- 用户选择目录确认时，最终目录生成后暂停；确认或调整后继续成文组织和写作。
- 两个检查点只在用户选择相应模式时启用；普通任务不额外等待。
- 知识图谱不是阻塞主流程的必经阶段。主流程可复用已有图谱；缺少或未覆盖新事实时标记待构建，由用户主动发起后台构建。
- 文档解析模式和材料对比模式在各自目标完成后结束，不进入普通报告写作链。

## 修改、版本与失败行为

- 用户讨论本身不会静默改写任务或报告；助手读取信息通过工具，变更通过提案或明确的检查点表单执行。
- 助手会话绑定其入口提供的上下文：任务/产物、任务草稿或所选材料。材料讨论不得越出所选材料；助手未读取到权威信息时应继续调用相应工具或明确说明未知，不能按文件名和摘要猜测。
- 接受需求或目录提案只应用到对应的待确认产物，不会因此额外启动一次完整生成。用户确认检查点后才排入后续流程。
- 已有报告的改写/增量运行直接作用于当前报告，不创建必须由用户接受的候选工作区。成功后保存不可变版本快照，用户可通过版本审阅查看差异并恢复历史版本。
- 重算范围遵循依赖关系，而不是一律从头运行：任务要求影响分析规划及下游；材料角色影响证据及下游；事实/推论影响其依赖的计划与正文；目录影响成文组织与写作；格式调整只影响渲染。
- 增量和交互重算开始前保存基线版本；工作队列捕获到失败时尝试恢复该基线。**服务被强制终止或进程崩溃时的自动原子回滚目前不作保证**，不可在界面或文档中宣称已实现。
- 版本快照内容完全相同则复用已有版本；版本号由数据库并发安全地分配。
- 暂停是协作式的：运行在安全边界停下，队列/执行轮次记录暂停状态。服务重启不能继续内存队列中的执行；任务需由用户恢复。阶段字段和值以当前状态协议为准，不承诺不存在的 paused_from_stage 或 failure_stage 字段。

## 内容与证据约束

- 材料事实必须保留到原材料和证据单元的来源链。
- 材料推论必须关联支撑事实并带置信度；外部补充不得伪装成材料事实或材料推论。
- 结构化解析、语义判断和流程协议分属不同职责；未知语义不得导致原始材料或事实被不可逆丢弃。
- 模板控制版式，并可提供结构、表达和材料使用参考；不得覆盖用户明确要求、事实准确性或证据边界。详见 [模板与软风格学习架构](template-style-learning.md)。

## 契约维护

阶段协议的单一代码来源是 app/workflow/stages.py；状态转移和用户检查点由 app/workflow/controller.py 与 app/workflow/checkpoints.py 执行。重要产品承诺应由对应的自动化测试验证，测试名称见代码地图。发现不一致时，先归类为“实现缺陷”或“产品决定变化”，再改代码或契约，避免复制粘贴形成多份真相。
