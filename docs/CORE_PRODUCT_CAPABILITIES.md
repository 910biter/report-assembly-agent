# 核心产品能力设计基线

## 1. 任务类型

| 类型 | 输入 | 输出 | 是否修改报告 |
|---|---|---|---|
| 首次生成 | 目标、材料、模板 | 初始报告版本 | 是 |
| 改写/补写 | 已有报告、修改目标 | 候选报告版本 | 用户审阅后生效 |
| 增量更新 | 已有报告、更新目标或新增材料 | 新报告版本与逐段差异 | 是，保留基线版本 |
| 新增材料对比 | 基线版本、新增材料、可选关注点 | 变化清单与影响分析 | 否 |

新增材料对比不得替代现有增量更新。其职责是发现新增、补强、细化、更新、冲突、削弱、无关和待确认信息。用户接受部分变化后，结果才作为带来源标识的输入交给现有增量更新。

## 2. 新增材料对比

```text
选择不可变基线版本
→ 解析新增材料
→ 材料理解与事实提取
→ 冲突检测与分析推论
→ 关键词 + 向量召回基线候选
→ LLM核验变化类型
→ 依据句子血缘计算报告影响
→ 用户集中审阅
→ 可选交接增量更新
```

对比条目独立绑定新增事实、基线事实、证据、影响位置、分类置信度和用户决策。相似度只负责召回候选，不能直接裁定冲突。

## 3. 异步用户介入

主流程默认连续执行，不在阶段边界等待用户。用户介入采用 `Human-on-the-loop`：

1. 对话绑定 `task_id + report_id + artifact_type + artifact_version + object_id`。
2. Agent只能解释或生成 `ChangeProposal`，不能在对话中直接修改产物。
3. 提案包含修改前后、理由、风险等级和下游影响。
4. 用户接受后，局部正文修改可直接形成小版本；上游语义修改进入待重组队列。
5. 基线产物和用户已经确认的版本始终保留。

影响边界：

| 修改对象 | 下游影响 |
|---|---|
| 任务目标 | Analysis Plan及全部下游 |
| 材料角色 | Evidence及全部下游 |
| Analysis Plan | Evidence及全部下游 |
| Fact | 依赖推论、规划和正文 |
| Inference | Final Plan、Narrative Plan和正文 |
| Final Plan | Narrative Plan和正文 |
| Narrative Plan | 对应章节正文 |
| 句子 | 血缘复核、QA和渲染 |
| 文档格式 | 仅渲染 |

## 4. 分层模板学习

`ReportProfile`由五层构成：

1. `DocumentTemplate`：原始DOCX与结构化OOXML Schema，负责渲染。
2. `StructurePolicy`：`FORMAT_ONLY / SOFT_STRUCTURE / HARD_STRUCTURE`。
3. `EditorialStyleProfile`：术语、句法、语气和段落组织。
4. `EvidenceUsageProfile`：选材、合并、具体性保持和事实到推论的习惯。
5. `ExemplarBank`：可按当前章节目的检索的已审核软范例。

学习资料分级：

| 资料 | 可学习内容 |
|---|---|
| 空白DOCX | 版式、编号、占位与结构提示 |
| 历史成品 | 语言和表面结构 |
| 材料 + 用户目标 + 审核报告 + 句子血缘 | 材料使用方式 |

未经审核的AI草稿不得进入范例库。多个DOCX发生冲突时保留完整变体，不跨文件拼接样式字段。

运行时按职责注入：Planner只读取结构策略；Evidence读取材料使用偏好但不得将其变成排除规则；Writer检索少量匹配范例；Renderer只读取原始DOCX和格式Schema。

## 5. 质量不变量

- Fact必须定位到Evidence和原始Unit。
- Inference必须绑定`based_fact_ids`和置信度。
- 变化分类不能仅由向量相似度决定。
- 对比任务不得修改基线报告。
- 用户讨论不能静默修改产物。
- 用户批准版本、系统生成版本和原始版本均可追溯。
- 模板风格不得覆盖事实准确性、证据完整性和用户明确要求。
